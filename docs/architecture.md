# 智卫 Sentinel 平台架构书（工程实现版）

## 1. 文档定位

本文件把项目申报书中的感知层、计算层、通信层、执行层和 Agentic 闭环转换为当前可以运行、可以审计、可以逐步接板验收的软件架构。它优先解决“硬件尚未齐备时，前端平台先搭稳”的问题，并对尚未验证的硬件和性能保持明确边界。

架构目标不是把模拟数据伪装成现场数据，而是让每一条数据都带有站点、设备、时间、序列、来源和质量，最后在前端以可理解的方式呈现给操作员。

## 2. 设计原则

1. **本地优先**：数据和决策默认在本地 FastAPI 服务完成，不依赖云端才能展示或判断。
2. **数据先验收再决策**：格式、单位、时间、顺序、设备能力和来源模式未通过时，不进入安全决策。
3. **来源不混用**：`live`、`simulated`、`replay` 按站点和数据库查询边界隔离；模拟数据不能覆盖真实数据。
4. **状态不等于健康**：业务风险状态（NORMAL/WATCH/ALERT/DANGER）与节点健康状态（online/delayed/offline）分开呈现。
5. **证据可追溯**：检测、状态流转、事件、命令和回执使用 `event_id`、`correlation_id`、`command_id` 串联。
6. **缺失不等于正常**：传感器缺失、节点离线、视觉过期时，系统进入数据不完整或降级提示，不主动把风险降为正常。
7. **真实执行必须有回执**：发送命令不等于动作完成，只有执行器返回 `completed` 才能在审计上写成完成。
8. **前端不猜测画面**：真实检测框必须和视频视角、来源模式、质量和 `frame_id` 对齐；无视频时只能显示明确标注的模拟元数据框。

## 3. 总体分层

```text
ESP32-S3 / K230（唯一摄像头） / Orange Pi（主推理） / Actuator
              │
       MQTT 或 HTTP 接入适配器
              │ 统一契约、令牌、时间、序列校验
              ▼
FastAPI API + SentinelHub
  ├─ 数据质量与顺序校验
  ├─ SQLite 持久化与游标
  ├─ 多模态 FSM 决策
  ├─ 事件/命令/回执审计
  ├─ 视频帧短缓存
  └─ WebSocket 实时发布
              │
              ├─ REST 权威快照和历史查询
              └─ WebSocket 快照、增量事件、健康、视频状态
              ▼
       前端 Dashboard（六个页面）
```

### 3.1 感知层

- ESP32-S3 预留温度、湿度、光照和心跳能力。
- K230 是唯一视觉采集节点，可上传板载辅助检测、模型版本、归一化框、序列和心跳。
- Orange Pi 3B 承担来自 K230 图像的主 AI 推理和本地 FSM 网关能力。
- 摄像头帧与检测元数据分开接入，平台只在两者能通过关联校验时绘制真实框。
- 执行器节点预留声光、风扇和继电器反馈能力。

### 3.2 计算和决策层

`SentinelHub` 维护当前站点和当前来源模式的最新数据、设备健康、状态机、事件、命令和视频缓存。`fsm.py` 是纯决策函数，输入只有经过质量筛选的数据和规则，不直接访问网络或 GPIO，便于单元测试和后续替换规则版本。

当前 FSM 规则包括：

- 光照较暗时进入 WATCH 候选，视觉阈值按规则调整。
- 温度达到 WATCH/ALERT/DANGER 阈值或温升过快时提高风险。
- 有效视觉火焰和环境热证据同时满足时才进入 DANGER。
- 高湿度会记录水雾排除证据；高光照会记录反光候选证据。
- 缺少环境或视觉输入时，状态可信度为 false，不能自动清除高风险状态。
- 风险恢复有持续观察时间，避免一次抖动立即清零。

原始申报书中的动态分辨率、INT8/FP16、RKNN、NNCase、15–25 FPS、毫秒级处置等属于后续硬件与模型验收目标；当前平台只接收标准化结果，不宣称这些结果已经测得。

### 3.3 通信和实时层

REST 用于设备接入、查询和受控命令；WebSocket 用于页面实时更新。每条 WebSocket 消息带 `stream_id` 和单调 `stream_sequence`。客户端发现流 ID 改变、序号缺口或收到 `resync_required` 时，会重新拉取 overview、events、detections、transitions、commands、config 和 telemetry history，以权威快照修复本地状态。

MQTT 适配器仅在 live 模式且配置 broker 时启动。它订阅遥测、检测、心跳和执行器反馈主题，拒绝 retained safety input、错误站点、错误设备主题、超大 payload 和模型契约校验失败的报文。

### 3.4 存储层

默认数据库为 `data/sentinel.sqlite3`。主要逻辑表包括：

| 数据 | 作用 |
| --- | --- |
| `devices` | 设备登记、能力、固件/模型版本和持久化健康信息 |
| `telemetry` | 遥测原始记录、质量、时间、序列、Boot ID |
| `detections` | AI 检测元数据和关联帧 ID |
| `events` | 告警、状态变化、命令事件和拒绝审计 |
| `transitions` | FSM 流转、规则版本和完整证据 |
| `commands` | 请求、发送、确认、完成、失败、超时历史 |
| `cursors` | 每个设备/来源/指标/Boot ID 的顺序游标 |

服务重启会保留上次风险状态，但将其标记为 `state_trusted=false`，等待新鲜完整数据复核。启动和测试不会清空默认数据库。

## 4. 统一数据契约

### 4.1 遥测

```json
{
  "eventId": "evt-uuid",
  "schemaVersion": "1.0",
  "siteId": "demo-site",
  "deviceId": "esp32-s3-001",
  "nodeType": "ESP32-S3",
  "channel": "environment",
  "metric": "temperature",
  "value": 23.6,
  "unit": "°C",
  "eventTime": "2026-10-09T00:00:00Z",
  "sequence": 1001,
  "bootId": "boot-uuid",
  "quality": "valid",
  "sourceMode": "live",
  "correlationId": "corr-uuid"
}
```

服务端生成或覆盖 `ingest_time`，不信任设备传入的接收时间。温度、湿度、光照有固定单位和值域；扩展指标仍需带单位并受有限数值校验。示例时间戳仅说明 ISO-8601 UTC 格式，接入时必须替换为实际采集时刻，不能重复发送固定的示例时间。

### 4.2 检测

检测必须说明 `device_id`、`camera_id`、`source_view`、`target`、`confidence`、归一化 `[x,y,width,height]`、`model_version`、`frame_id`、`event_time`、`sequence`、`boot_id` 和来源模式。新检测统一 `camera_id=k230-001`、`source_view=k230`，推理设备为 `orange-pi-001` 或 `k230-001`。状态机只采用新鲜的香橙派主推理且要求 K230 在线；同一摄像头的两份推理不算独立视觉证据。历史 `main` 记录只保留审计，不接受新的 `main` 输入。

### 4.3 视频

视频接入只接受 JPEG，限制大小、签名和时间新鲜度。平台只保留最近少量帧在内存中，不把视频帧写入 SQLite。前端读取 `/api/v1/video/{view}/frame?frame_id=...` 时使用 `Cache-Control: no-store`，避免将旧帧误当成实时画面。

### 4.4 命令和回执

命令状态：`accepted → sent → acknowledged → completed`，异常路径为 `failed` 或 `timeout`。真实模式下，`completed` 必须来自执行器回执，不由浏览器或网关猜测。`reset` 是执行器请求，不会强行把 FSM 风险状态改成 NORMAL。

## 5. 前端信息架构

| 页面 | 主要信息 |
| --- | --- |
| 态势总览 | 权威 FSM、环境卡片、实时趋势、节点健康、视觉占位、事件链 |
| 实时监控 | 双视角视频状态、检测元数据、真实/模拟框边界 |
| 事件中心 | 告警确认、FSM 审计、命令状态和回执 |
| 设备与质量 | 设备能力、心跳状态、最新遥测和质量规则 |
| 历史数据 | 原始单位曲线、设备/来源筛选、采集/接收时间和质量原因 |
| 接入与接口 | 统一契约、REST 预留接口、运行配置、控制令牌和接板顺序 |

页面始终显示模拟或真实来源横幅。`stale` 会保留最后数值帮助排障，但卡片、曲线和状态证据都会显示过期，不会假装实时。

## 6. 安全和部署边界

- 默认只监听本机，局域网部署前应配置防火墙和反向代理。
- 控制令牌和设备令牌是当前版本的共享令牌，不是完整 RBAC；不得把它们提交到仓库或写入前端源码。
- 真实模式建议独立数据库、独立站点 ID 和独立 broker 凭据。
- MQTT 真实安全输入禁止 retained message 建立实时状态。
- 事件和错误日志不得记录设备密码、令牌或原始敏感视频。
- 默认 CSP 禁止任意脚本和远程图片；Swagger UI 可能因 CDN 离线而不可用。
- 物理执行必须有硬件急停、保险、继电器隔离、断电安全态和人工验收。

## 7. 分阶段验收

### 阶段 A：平台联调（当前）

使用模拟数据验证六个页面、48 秒周期、WebSocket 重同步、事件确认、命令审计、历史查询和数据质量标签。

### 阶段 B：传感器和视觉输入

只接 ESP32-S3、K230、Orange Pi 和摄像头，不打开物理执行。验收时间同步、丢包、乱序、重启换 Boot ID、断网和恢复；对照画面验证 `frame_id`。

### 阶段 C：执行器反馈

接入隔离继电器和执行器适配器，先只做人工命令和回执闭环。确认 acknowledged/completed/failed/timeout 的状态和审计完全一致。

### 阶段 D：现场安全验收

在硬件联锁、急停、断电、安全评估、误报/漏报测试、延迟和帧率实测完成前，不打开自动物理执行。申报书中的性能数字只能在该阶段测量后填写。
